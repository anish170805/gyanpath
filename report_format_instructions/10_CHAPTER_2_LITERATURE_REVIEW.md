# CHAPTER 2 — LITERATURE REVIEW

## Heading format

```text
CHAPTER 2
LITERATURE REVIEW
```

## Required section sequence
1. `2.1 Introduction`
2. `2.2 Existing <Domain Systems / Platforms>`
   - Add named system subsections such as `2.2.1`, `2.2.2`, `2.2.3`.
3. `2.3 <Foundational System/Technology Category>`
4. `2.4 <Core AI/Technical Area>`
5. `2.5 <Supporting Technical Area>`
6. Additional related technical areas.
7. `2.11 Existing Research Work` or equivalent, adjusted only if actual structure requires a different number.
8. `2.12 Comparison of Existing Systems`
9. `2.13 Research Gap`
10. `2.14 Summary`

## What to write
### Existing systems/platforms
For each:
- what it is,
- major features,
- advantages,
- limitations relevant to your project,
- what gap remains.

### Technical concepts
Explain relevant technologies and research areas using:
- definition,
- core methods/components,
- applications,
- strengths,
- limitations.

### Existing research work
Discuss actual prior work relevant to the project. Do not invent papers or research claims.

### Comparison table
Use a feature-comparison table.

Required pattern:

| Feature | Existing System A | Existing System B | Proposed System |
|---|---|---|---|
| <Feature> | <Status> | <Status> | <Status> |

Use factual statuses such as `Available`, `Limited`, `Manual`, `Partial`, `Integrated`, or actual measured differences.

### Research Gap
List concrete gaps found after reviewing existing systems and research. Then explain how the proposed project addresses them.

### Summary
Summarize reviewed systems, technologies, findings, and the identified gap.

## Project-folder instruction
Use actual competitor/system research and project requirements stored in `<PROJECT_ROOT>/project-source/`. Every comparison claim must be supportable by source material.

## Image rule
Do not add decorative images. If a comparison architecture or taxonomy diagram is necessary, reserve space using the standard image placeholder.
