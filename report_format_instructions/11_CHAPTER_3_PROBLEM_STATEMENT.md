# CHAPTER 3 — PROBLEM STATEMENT

## Heading format

```text
CHAPTER 3
PROBLEM STATEMENT
```

## Required section sequence
1. `3.1 Introduction`
2. `3.2 Existing System Problems`
   - Use nested problem headings: `3.2.1`, `3.2.2`, ...
3. `3.3 Proposed System`
   - Use nested solution headings: `3.3.1`, `3.3.2`, ...
4. `3.4 Objectives of Proposed Solution`
5. `3.5 Expected Outcomes`

## What to write
### 3.1 Introduction
Describe the domain problem and why current approaches are insufficient.

### 3.2 Existing System Problems
Break each problem into a separate numbered subsection. For every problem:
- describe the current limitation,
- explain its impact,
- avoid proposing the solution too early.

### 3.3 Proposed System
Explain how the proposed project addresses each major problem. Break by major capability/module.

### 3.4 Objectives of Proposed Solution
Use a numbered list of concrete objectives.

### 3.5 Expected Outcomes
Use bullets to state measurable or observable outcomes. Do not claim results that have not been implemented/tested.

## Project-folder instruction
Map every problem and proposed solution to evidence from `<PROJECT_ROOT>/project-source/`.
